# 工业级异步微服务网关安全与高并发实战笔记

## 一、 实战目标
基于 Python asyncio 构建高并发微服务网关，整合分布式 Token 桶限流、HMAC-SHA256 签名鉴权、防重放攻击、超时熔断及优雅停机（Graceful Shutdown）机制。

## 二、 核心架构模块与技术实现
1. **异步队列与并发调度**：
   - 使用 `asyncio.Queue` 实现解耦的任务缓冲区。
   - 通过 `asyncio.create_task` 派生常驻 Worker 协程池（默认并发数 3），消费队列任务。
2. **多维安全防御矩阵**：
   - **防重放攻击**：校验 `timestamp` 漂移时间窗口，结合 `request_id` 去重缓存拦截重复请求。
   - **数据防篡改**：基于 `hmac.compare_digest` 校验 HMAC-SHA256 签名，防御中间人篡改与时序攻击。
   - **分布式限流**：实现 `AsyncTokenBucketRateLimiter` 令牌桶算法，防止高并发倾泻式流量（DoS/CC）。
   - **超时熔断**：通过 `asyncio.wait_for` 监控下游服务耗时，超过阈值（如 1.0s）主动触发 504 熔断。
3. **异常处理与死信队列（DLQ）**：
   - 对捕捉到的 SQL 注入特征码及 500 系统级崩溃异常进行隔离，并自动转投至 `dead_letter_queue` 供离线审计。
4. **生命周期管理与优雅停机**：
   - 维护 `is_running` 状态标志，关机时停止接收新流量。
   - 调用 `task_queue.join()` 确保存量任务全部处理完毕后，安全取消 Worker 协程并清点处理结果。

## 三、 排错与复盘记录
- **问题现象**：在启动测试时，Worker 协程启动后瞬间退出，且抛出 `RuntimeError: 网关未启动, 拒绝接受新流量!`。
- **原因分析**：启动逻辑中状态位赋值存在语法错误（多写了 `=` 符号），导致 `is_running` 未正确更新为 `True`，Worker 进入 `while` 循环条件不成立直接退出。
- **修复方案**：修正状态位赋值逻辑，确保在拉起 Worker 协程池之前将 `is_running` 正确置为 `True`。

## 四、 压测演练输出摘要
- 成功完成正常流量、超时熔断（504）、SQL 注入捕获（500）、重放攻击拦截（401）及高频限流（429）的联合防御测试。
- 全生命周期优雅停机流程正常收尾，死信队列成功归档异常记录。
