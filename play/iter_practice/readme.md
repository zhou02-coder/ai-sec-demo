## 项目简介
本项目围绕Python迭代协议整套体系搭建，从底层手写迭代器、可迭代对象，到yield生成器高阶用法，再对比生成器表达式与列表推导式的性能差异，最后落地企业常见的超大日志文件流式读取场景。
核心目标：理解Iterable与Iterator的协议区别、惰性求值思想；学会使用生成器处理大数据，规避内存溢出（OOM）问题。

## 项目特性
1. 严格遵循Python迭代协议规范，手动实现`__iter__`、`__next__`方法，直观区分【可迭代对象】和【迭代器】
2. 演示迭代器一次性消耗特性、可迭代对象重复遍历特性，理清二者核心差异
3. 实现交互式生成器，支持`send()`外部传值、`throw()`捕获异常、`close()`资源清理，覆盖生产级生成器高阶API
4. 增加性能对照模块，量化对比列表推导式（立即求值）和生成器表达式（惰性求值）的内存占用、运行速度
5. 业务实战模块：基于生成器实现大文件逐行流式读取，全程仅单行数据驻留内存，适配GB级日志文件
6. 代码模块化分区，统一入口控制测试开关，按需启用模块测试，互不干扰
7. 注释采用中英双语标注，区分基础知识点和视频以外拓展内容
8. 额外厘清容易混淆概念：文件对象天然是迭代器、with上下文管理器只负责资源回收，不改变对象迭代属性

## 核心知识点梳理
1. 迭代协议规则
    - 可迭代对象（Iterable）：实现`__iter__`，for循环的目标，可以重复遍历
    - 迭代器（Iterator）：同时实现`__iter__`和`__next__`，一次性消耗，耗尽之后无法产出数据
    - 从属关系：迭代器一定是可迭代对象，可迭代对象不一定是迭代器；生成器属于迭代器
2. yield生成器原理：函数遇到yield暂停，保留局部变量状态，next()从暂停位置继续执行
3. 惰性求值：生成器不会预先计算并保存全部数据，需要时实时计算，内存开销极低
4. 文件对象特性：open成功返回的文件对象本身就是迭代器；with仅自动关闭文件句柄，和迭代能力相互独立

## 学习复盘
本次学习打通了从底层协议到业务落地的完整链路。前期容易混淆“可迭代对象”和“迭代器”，通过手写类的方式直观感受到两者区别；生成器的send/throw/close属于视频之外拓展内容，理解难度更高。
重点收获：理解惰性求值的工程价值，以后处理大批量数据优先考虑生成器流式方案，避免一次性加载全部数据造成内存溢出。
踩坑点：迭代器只能遍历一次；生成器未启动时，不能直接send非None值；区分文件指针重置seek()和迭代协议本身规则。s
