# Python 多线程实战 - 互斥锁 & 竞态条件
> Date: 2026-10-23
> Description: 基于原生 threading 实现，验证竞态条件、锁粒度、join行为，采用OOP封装管理共享状态，不使用线程池，侧重底层原理验证。

## 📚 核心知识点
1. **线程 Thread**
同一进程内多个线程共享内存空间，共享变量会引发数据竞争。
2. **竞态条件 Race Condition**
`count += 1` 不是原子操作：读取 → 自增 → 写回。多线程并发执行会覆盖写入，最终数值小于预期。
3. **互斥锁 threading.Lock()**
保证临界区同一时刻只允许一个线程进入。
- `with lock:` 【推荐】上下文管理器，正常结束 / 抛出异常都会自动释放锁，避免死锁
- `lock.acquire()` + `lock.release()`：手动管理，异常时容易忘记释放锁，造成死锁
4. **join()**
主线程阻塞等待子线程执行完成后再继续。
> ⚠️ 重要误区：`join()` 只控制执行时序，**不能保护共享变量，无法解决资源竞争**
5. **临界区 & 锁粒度**
- 细粒度锁：仅包裹修改共享变量的代码，并发性能更好（工程首选）
- 粗粒度锁：大量代码/整个循环包裹在锁内，并发失效，接近串行执行
6. **OOP 封装思路**
- `self._count`：约定私有变量，存放共享计数，仅类内部读写
- `self._lock`：约定私有锁对象，和共享状态绑定
- `@property`：对外只读访问，外部不可直接赋值，保护内部状态
